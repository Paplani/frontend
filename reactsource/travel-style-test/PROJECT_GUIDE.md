# 나의 여행 스타일 테스트 — 구현 안내

React 연습용 창작 테스트입니다. 심리검사나 성격 진단이 아니며, 결과는 이번에 고른 답변의 경향을 재미로 보여줍니다.

## 오늘 만들 범위

질문 8개, 질문마다 선택지 4개, 결과 유형 4개입니다.
시작 → 질문 → 결과의 세 화면을 만듭니다. 질문 화면은 하나를 재사용하고 질문 데이터만 바꿉니다.
Router는 필수가 아닙니다. 이번에는 화면 상태와 조건부 렌더링으로 구현해도 충분합니다.
로그인, 서버, 데이터베이스, 배포, 새로고침 후 복원은 기본 범위에 포함하지 않습니다.

## 준비된 파일과 데이터 모양

- public/data/questions.json: 질문 배열. 각 질문은 id(숫자), text(문자열), options(선택지 배열)를 가집니다.
- 각 선택지는 id(문자열), text(문자열), type(결과 유형 식별자)를 가집니다.
- public/data/results.json: 결과 배열. type, name, emoji, tagline, description, strengths(문자열 배열), suggestions(문자열 배열), tripIdea를 가집니다.
- type은 planner, explorer, relaxer, connector 중 하나입니다.
- 브라우저에서 불러올 경로는 /data/questions.json과 /data/results.json입니다. public은 요청 경로에 넣지 않습니다.
- 직접 TypeScript 타입을 설계해보세요. 질문 한 개와 질문 배열, 선택지 한 개와 선택지 배열을 구분하세요.
- type은 내부 계산용이며 선택지 버튼에는 text만 표시합니다.

## 점수 규칙

1. 질문마다 답은 하나만 선택합니다. 선택지 순서는 유형별로 섞여 있습니다.
2. 선택한 답의 type에 1점을 줍니다. 8개 답변의 총점은 반드시 8점입니다.
3. 가장 높은 점수를 얻은 유형이 결과입니다.
4. 공동 1위라면 마지막 질문부터 답변을 거꾸로 살펴봅니다. 공동 1위 유형 중 가장 최근에 선택한 유형을 결과로 정합니다.
5. 이전 질문에서 답을 바꾸면 예전 답을 대체합니다. 클릭할 때마다 점수를 누적하지 말고, 최종 답변에서 점수를 계산하는 방식을 권장합니다.

계산 예: planner 3점, explorer 3점, relaxer 1점, connector 1점이면 planner와 explorer만 동점 후보입니다.
8번 답이 relaxer, 7번 답이 explorer라면 explorer가 결과입니다. 8번 답이 전체 동점 후보에 없으므로 건너뜁니다.

## 화면별 요구사항

### 시작 화면

제목: 나의 여행 스타일은?
소개: 낯선 도시에서 당신은 어떤 하루를 보내고 싶나요? 8개의 질문으로 나만의 여행 스타일을 만나보세요.
버튼: 테스트 시작
보조 문구: 약 2분 · 정답은 없어요. 지금 가장 끌리는 답을 골라주세요.
시작을 누르면 첫 질문으로 이동합니다.

### 질문 화면

- 현재 질문 번호와 전체 개수, 질문 문장, 선택지 4개를 표시합니다.
- 선택한 답은 색이나 테두리로 확실하게 구분합니다.
- 답을 선택해도 자동으로 다음 질문으로 넘어가지 않습니다.
- 선택하지 않은 질문에서는 다음 버튼을 비활성화합니다.
- 첫 질문에서는 이전 버튼을 숨기거나 비활성화합니다.
- 이전/다음으로 돌아왔을 때 기존 선택을 유지합니다.
- 마지막 질문의 다음 버튼 문구는 결과 보기입니다.
- 모든 질문에 답한 경우에만 결과를 보여줍니다.
- 진행 표시는 '현재 질문 3 / 8'처럼 기준을 명확히 정합니다.
- 선택지는 실제 button 요소로 만들어 키보드로도 선택할 수 있게 해보세요.

### 결과 화면

결과의 emoji, name, tagline, description, strengths, suggestions, tripIdea를 표시합니다.
보조 문구: 선택한 답변을 바탕으로 한 재미용 결과예요. 여행 스타일은 상황과 동행에 따라 달라질 수 있어요.
다시 하기 버튼을 누르면 답변과 진행 위치를 초기화하고 시작 화면으로 돌아갑니다.

### 데이터 요청 상태

가져오는 동안: 여행 질문을 준비하고 있어요…
가져오기에 실패하면: 질문을 불러오지 못했어요. 잠시 후 다시 시도해 주세요.
데이터가 준비되기 전에는 테스트를 시작하지 못하게 합니다.
HTTP 오류와 JSON 처리 실패도 생각해보세요.

## 구현 순서와 생각할 질문

- [ ] 질문과 결과 JSON을 열어 구조를 이해하고 타입을 정한다.
- [ ] 질문 데이터를 불러와 첫 질문과 선택지 4개를 표시한다.
- [ ] 선택지 하나를 선택하고 선택 표시를 바꾼다.
- [ ] 답변을 저장한다. 질문 id와 선택지 id를 어떻게 연결할까?
- [ ] 이전/다음 이동을 만든다. 다시 돌아오면 어느 답이 선택되어 있어야 할까?
- [ ] 선택하지 않은 경우 이동을 막는다.
- [ ] 저장된 답변으로 유형별 점수를 계산한다.
- [ ] 동점 규칙을 적용해 결과 하나를 고른다.
- [ ] 결과 데이터를 찾아 결과 화면을 표시한다.
- [ ] 다시 하기와 로딩/오류 표시를 만든다.
- [ ] 마지막에 Tailwind로 화면을 꾸민다.

부모가 관리할 상태와 자식이 전달할 이벤트를 먼저 종이에 적어보세요.
질문 내용은 데이터이고, 선택한 답과 현재 화면은 사용자 행동에 따라 변하는 상태입니다.
컴포넌트 후보: 시작 화면, 질문 화면, 선택지 버튼, 진행 표시, 결과 화면.
모두 나눌 필요는 없습니다. 반복되거나 역할이 분명한 부분부터 분리하세요.
컴포넌트 구현과 결과 계산의 정답 코드는 제공하지 않습니다. 막히면 현재 코드와 생각한 방향을 바탕으로 힌트를 요청하세요.

## 직접 확인할 완료 기준

- 한 질문에서 여러 번 클릭해도 답변은 하나다.
- 이전 질문의 답을 바꾸고 돌아오면 새 답이 유지된다.
- 8개 답변 이후 총점은 8이다.
- 질문 1~8의 선택지 번호를 1, 3, 4, 2, 1, 3, 2, 4로 고르면 planner 8점이다.
- 1, 3, 1, 3, 2, 2, 2, 3으로 고르면 planner 3, explorer 3, relaxer 1, connector 1이고 결과는 explorer다.
- 1, 3, 1, 3, 4, 3, 4, 2로 고르면 planner 3, explorer 3, relaxer 1, connector 1이고 결과는 planner다. 마지막 두 답이 동점 후보가 아닌 경우도 확인한다.
- 다시 하기를 누르면 이전 선택이 남지 않는다.
- 데이터를 불러오지 못해도 빈 화면만 남지 않는다.
- 선택지가 길어도 글자가 잘리거나 버튼이 겹치지 않는다.

유형별 점수 막대, 결과 화면 저장, 선택지 전환 효과 중 하나만 추가해보세요.
먼저 기본 흐름을 완성하는 것이 목표입니다.
